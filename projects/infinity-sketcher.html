PROJECT 01 · CNC · EMBEDDED · COMPUTER VISION

Infinity Sketcher

A compact differential-drive CNC drawbot with a complete image-to-motion pipeline. The PC performs vision, path planning, kinematics and simulation while the Arduino executes synchronized motor steps and hardware safety logic.

INFINITY SKETCHER · PROJECT VEHICLE

SYSTEM

Smart Host, Dumb Executor

Python is the computational host for image processing, pathfinding, floating-point kinematics and coordinate mapping. Arduino remains focused on deterministic motor execution.

HARDWARE

Differential-drive CNC

Arduino, dual NEMA 17 stepper motors, driver modules and a pen-lift servo form the physical drawing platform.

SOFTWARE

OpenCV + Tkinter

Image import, preprocessing, contour/skeleton tracing, path ordering, simulation, parameter tuning and serial machine control.

CONTROL

Synchronization + PID

Bresenham-style pulse interleaving, trapezoidal acceleration and straight-line PID correction keep the two-wheel system coordinated.

THE BUILD

From image to motion.

The physical machine, software pipeline and control firmware are treated as one system.

SYSTEM ARCHITECTURE & ALGORITHMS REVIEW

Engineering internals

01 — Differential-drive kinematics

The paper coordinate system uses +Y as Up/North and +X as Right/East. Heading θ starts at 0° along +Y and increases clockwise.

S_mm = (Full Steps × Microsteps) / (π × Wheel Diameter)

S_deg = (π × Axle Width / 360) × S_mm

Wheel distances are converted into center displacement and heading change using differential-drive geometry.

02 — Image-to-stroke pipeline

  1. Scale the source image toward a thin working resolution.
  2. Auto-invert when required.
  3. Apply binary thresholding to form a drawing mask.
  4. Extract contours with Suzuki-Abe.
  5. Simplify paths with Douglas-Peucker / approxPolyDP.

The planner then orders strokes using a greedy nearest-neighbor variation of the Traveling Salesperson Problem, checking both endpoints and reversing strokes when the far endpoint is closer.

03 — Toolpath generation

Drawing strokes are divided into small segments. For each segment the robot rotates toward the next bearing and drives forward. Fine segmentation produces smooth-looking curves while retaining sharp corners.

04 — Arduino execution

Bresenham synchronization interleaves left and right pulses so unequal step counts complete together. Trapezoidal acceleration ramps pulse timing at the beginning and end of a move. For straight commands, PID correction compares executed left/right steps and adjusts timing to counter mechanical asymmetry.

05 — Concurrency and serial reliability

Tkinter stays responsive by moving OpenCV processing, path planning and blocking serial work into daemon background threads. UI updates return to the main event loop with self.after(0, ...). The serial protocol is synchronous: Python clears stale input, sends one command, then waits for the Arduino response. STOP is handled as an immediate override.

06 — Live simulation and coordinate spaces

The GUI separates screen coordinates from mathematical coordinates. A mirror flag can invert Y for physical planning while rendering reverses that transformation for an intuitive preview. The live preview is based on simulated motor steps and the same forward-kinematics model used for the physical robot.

07 — Skeletonization and the double-outline problem

Thick raster strokes can otherwise generate inner and outer contours. The documented approach uses morphological skeletonization with a 3×3 structuring element, iteratively combining eroded/dilated layers into a one-pixel-wide central spine. This is intended to produce one physical pass per stroke.

08 — Workshop-oriented UI

The documented GUI favors high-contrast controls and editable sensitive parameters such as Axle Width, Wheel Diameter and PID gains. Exact typing provides precision; mouse-wheel modulation supports rapid tuning while observing the machine.

09 — Reliability and safety

FLT_L and FLT_R provide driver fault detection. A fault triggers the stop path and motor disable. EN_ALL removes coil power while idle. The host also calculates a dynamic command timeout rather than waiting indefinitely.

10 — Roadmap

The documented roadmap includes IMU-assisted slip correction, wireless host-to-robot communication and optical-flow position tracking.
