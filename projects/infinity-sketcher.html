PROJECT 01 · CNC · EMBEDDED · PYTHON

Infinity Sketcher

A compact differential-drive CNC drawbot with a complete image-to-motion pipeline: the PC handles vision, path planning and kinematics while the Arduino executes synchronized motor steps.

INFINITY SKETCHER · CLEAN MACHINE CUTOUT

SYSTEM

Smart Host, Dumb Executor

Python is the computational host for image processing, pathfinding, floating-point kinematics and coordinate mapping. Arduino remains focused on deterministic motor execution.

HARDWARE

12 × 12 cm CNC drawbot

Arduino, dual NEMA 17 stepper motors and DRV8825-class stepper drivers, with shared enable and hardware fault inputs.

SOFTWARE

OpenCV + Tkinter

Image upload, preprocessing, contour extraction, path ordering, simulation, parameter tuning and serial machine control.

CONTROL

Synchronization + PID

Bresenham-style pulse interleaving, trapezoidal acceleration and straight-line PID correction keep the two-wheel system coordinated.

THE BUILD

From image to motion.

The physical machine, software pipeline and control firmware are treated as one system.

SYSTEM ARCHITECTURE & ALGORITHMS REVIEW

Engineering internals

01 — Differential-drive kinematics

The paper coordinate system uses +Y as Up/North and +X as Right/East. Heading θ starts at 0° along +Y and increases clockwise.

S_mm = (Full Steps × Microsteps) / (π × Wheel Diameter)

S_deg = (π × Axle Width / 360) × S_mm

For a left/right command, wheel distances are computed first, followed by center displacement and heading change:

d = (d_L + d_R) / 2    Δθ = (d_R − d_L) / Axle Width

02 — Image-to-stroke pipeline

  1. Scale the source image toward a thin working resolution.
  2. Auto-invert when required so ink becomes black on white.
  3. Apply a binary inverse threshold to form a drawing mask.
  4. Extract contours with the Suzuki-Abe method.
  5. Simplify paths with Douglas-Peucker / approxPolyDP.

The planner then orders strokes using a greedy nearest-neighbor variation of the Traveling Salesperson Problem, checking both endpoints and reversing strokes when the far endpoint is closer.

03 — Toolpath generation

Arbitrary curves are approximated with small linear segments. For each segment the robot rotates in place toward the next bearing and then drives straight for the segment distance. Small segments create a visually continuous curve while preserving sharp corners.

04 — Arduino execution

Bresenham synchronization interleaves left and right pulses so unequal step counts complete together. Trapezoidal acceleration ramps pulse timing at the beginning and end of a move. For straight commands, PID correction compares executed left/right steps and adjusts timing to counter mechanical asymmetry.

05 — Concurrency and serial reliability

Tkinter stays responsive by moving OpenCV processing, path planning and blocking serial work into daemon background threads. UI updates are returned to the main event loop with self.after(0, ...). The serial protocol is synchronous: Python clears stale input, sends one command, then waits for the corresponding Arduino response. STOP is handled as an immediate override.

06 — Live simulation and coordinate spaces

The GUI separates screen coordinates from mathematical coordinates. A mirror flag can invert Y for physical planning while rendering reverses that transformation for an intuitive preview. The live preview is based on simulated motor steps and the same forward-kinematics model used for the physical robot, providing a WYSIWYG motion check.

07 — Skeletonization and the double-outline problem

Thick raster strokes can otherwise generate inner and outer contours. The documented approach uses morphological skeletonization with a 3×3 cross-shaped structuring element, iteratively combining eroded/dilated layers into a one-pixel-wide central spine. This is intended to produce one physical pass per stroke.

08 — Workshop-oriented UI

The documented GUI favors high-contrast black text on warm beige/white surfaces and replaces sensitive sliders such as Axle Width, Wheel Diameter and PID Gains with editable fields. Exact typing provides precision; mouse-wheel modulation supports rapid tuning while observing the machine.

09 — Reliability and safety

FLT_L (Pin 9) and FLT_R (Pin 10) use pull-ups for hardware fault detection. A fault triggers stopFlag and motor disable. EN_ALL (Pin 8) is used to remove coil power while idle. The host also calculates a dynamic command timeout with a safety margin rather than waiting indefinitely.

10 — Problem, solution and roadmap

Infinity Sketcher fixes trajectory drift by offloading path optimization to a PC and using real-time PID correction on the Arduino for precise motor execution.

The documented roadmap includes an IMU for slip correction, wireless communication through HC-05 or ESP32, and downward-facing optical-flow tracking to reduce dependence on wheel odometry.
